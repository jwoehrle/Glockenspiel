# Mein Glockenspiel

A small web app for learning songs on a children's glockenspiel (Sonor GS Toysound: eleven bars, c3–f4 in C major:
C D E F G A H c d e f). The three highest bars (d e f) have the same colors as the low D E F, and the high c matches
the low C. It shows the next color/note and listens through the microphone to check whether the right bar was struck.

- Live: https://jwoehrle.github.io/Glockenspiel/
- Installable as an app (PWA) and usable offline.
- TypeScript + Vite, no UI framework. Unit tests with Vitest, end-to-end tests with Playwright.

## Development

Requirement: Node.js 22 or newer.

```bash
npm install
npm run dev
```

Then open <http://localhost:5173/Glockenspiel/> (Chrome recommended). Changes reload automatically.

| Command                    | What it does                                                               |
| -------------------------- | -------------------------------------------------------------------------- |
| `npm run dev`              | Dev server with hot reload                                                 |
| `npm run check`            | Type-check, lint, format check, unit tests                                 |
| `npm run test:e2e`         | Build and serve the production site, run the Playwright tests (Chromium)   |
| `npm run test:e2e:preview` | Build the live site + a PR preview in the gh-pages layout, test both       |
| `npm run build`            | Production build into `dist/`                                              |
| `npm run preview`          | Serve `dist/` at <http://localhost:4173/Glockenspiel/> (with offline mode) |
| `npm run format`           | Format all files with Prettier                                             |

The first time you run the e2e tests, install the browser with `npx playwright install chromium`.
The e2e tests also exercise the microphone detection: Chromium's fake microphone plays synthetic glockenspiel
recordings, generated by `tests/e2e/fixtures.ts`.

Notes:

- **Microphone:** only works in a secure context. `localhost` counts as one. The browser asks for microphone
  permission the first time you tap a song.
- **Service worker:** only active in the production build (`npm run build && npm run preview`), not in `npm run dev`.
- **Settings are separate per address:** `localhost` and the live site each have their own calibration and options
  (stored in `localStorage`).

### Testing on a phone

`http://<laptop-ip>:5173` has no microphone on the phone (no HTTPS). Use Chrome port forwarding instead:

1. Connect the phone via USB and enable USB debugging on it.
2. On the laptop, open `chrome://inspect/#devices`.
3. Under _Port forwarding_, add `5173` → `localhost:5173` and enable it.
4. On the phone, open `http://localhost:5173/Glockenspiel/` in Chrome.

## Usage

- **Tap a song tile:** starts the song and turns the microphone on.
- **🎤** microphone on/off · **🔊** play the current note · **▶** play the whole song (⏹ stops) · **🔁 Von vorn**
  restart the song · **🏠** back to the song list. While the song plays, the circle and the glockenspiel show each note.
- **Without a glockenspiel:** tap the big circle to play the current note and move on.
- **On a tablet or laptop**, the whole glockenspiel is shown below the circle (portrait) or beside it (landscape), and
  the bar to strike pops out.
  Tap the bars to play the song on the screen: the right bar moves on, a wrong one only wobbles.
- **Parent area:** press and hold the ⚙ in the top-right corner for about 1 second. It contains: autoplay, read the
  color aloud, staff notation (_Noten anzeigen_: the current and next note in a treble clef left of the circle, on
  tablets and laptops), microphone sensitivity, one note back, calibration, and clearing saved data.

### Calibration (optional)

In the parent area, tap _Kalibrieren_ and strike the eleven bars one at a time. The app stores the measured
frequencies and then checks against those (±50 cents) instead of standard tuning. For a normally tuned glockenspiel
this isn't needed.

## Adding songs

Add an entry to `SONGS` in `src/songs.ts`:

```ts
meinlied: {
  icon: "🐝",
  title: "Title",
  bpm: 100, // quarter notes per minute
  notes: build(
    [
      "Line-|C one|D here|E",
      "Line-|F two|G now|AB", // two letters = two notes on one syllable
    ],
    [
      "4 4 2", // one length per note
      "4 4 8 8 r4", // r4 = quarter rest after the previous note
    ],
  ),
},
```

Format: `syllable|note`, where notes are `C D E F G A H c d e f` (lowercase = the high bars on the right). Use `_`
for a space inside a syllable. Only use notes within the C–f range, with no sharps or flats. Detection checks the
octave too, so `D` and `d` are different bars. Lengths are LilyPond-style: `1 2 4 8 16`
(whole … sixteenth), a dot for dotted notes (`4.`), `+` to tie (`4+16`). `build()` rejects unknown notes and rhythm
lines that don't match the notes, and `npm run check` verifies that every song is valid and every icon is unique.

## Deployment and previews

`.github/workflows/pages.yml` publishes through the `gh-pages` branch:

| Event                         | What happens                                                                                                                                                 |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Pull request opened / updated | Tests, then a **preview** at `https://jwoehrle.github.io/Glockenspiel/pr-preview/pr-<n>/`; the link (and a QR code for the tablet) is posted as a PR comment |
| Pull request closed / merged  | The preview is removed                                                                                                                                       |
| Push to `main`                | Tests, then the **live site** at <https://jwoehrle.github.io/Glockenspiel/> (previews are kept)                                                              |

Tests = type-check, lint, format check, unit tests, the Playwright e2e tests and the e2e tests of the gh-pages
layout. Nothing is published if a test fails.

Workflow: create a branch, push it, open a pull request to `main`, try the preview (e.g. on the tablet), then merge.

Previews show a small "Vorschau PR n" label, have their own service worker, offline cache, manifest name and
saved settings, so they never mix with the live app. To try the same layout locally:
`npm run test:e2e:preview` (builds the live site and a preview into `.site/` and tests both).

Repository settings:

- **Settings → Pages → Source:** "Deploy from a branch", branch `gh-pages`, folder `/ (root)`.
- Recommended: **Settings → Branches → branch protection for `main`**: require a pull request and the status check
  `test` before merging.

Installed apps update automatically: a new deployment produces a new service worker, which takes over on the next
visit; the update is visible after one reload.
